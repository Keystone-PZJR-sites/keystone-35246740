## 6 · Motion

Intent supplied by design 2026-08-24; values chosen here and approved with
the spec. The ease-out curve below is 004's close curve
`cubic-bezier(0.22, 1, 0.36, 1)`; the ease-in-out is 004's open curve
`cubic-bezier(0.65, 0, 0.35, 1)`. All constants live in the component token
layer; the constants shared with 004 (250ms · the two curves · the 200ms
shadow growth) now have a second consumer — promoting them to a global
motion-token layer is part of this phase (004 §5 deferred it to exactly
this moment).

1. **nav-button hover.** A 1px underline in `text/600` grows in along the
   bottom edge of the full cell (not the text width): `scaleX(0) →
   scaleX(1)`, `transform-origin: center`, **320ms** ease-out. Built as a
   scaling pseudo-element (a border cannot transform). Label ink
   `text/300` → `text/100` over 180ms ease. Chevron rotates 180° (up) over
   **300ms** ease-out; it also holds rotated while the submenu is open.
   Mouse-out reverses everything on the same curves. Hover rules sit under
   hover-capable media (004 pattern).
2. **Login button.** Underline and ink as above; instead of a chevron its
   arrow animates like the footer Login (004 §4): label→arrow gap grows
   3 → 5 with the hover ink shift.
3. **Subnav reveal (desktop).** On hover intent over a trigger: the drawer
   fades 0→1 (**180ms** ease) with a slide from translateY(−6px)→0
   (**240ms** ease-out). Inside, each block — every subitem card, each
   label cell, the feature card — starts at opacity 0 / translateY(12px)
   and lands at 1 / 0: opacity **320ms** ease, transform **380ms**
   ease-out. Blocks stagger **50ms** apart, starting **60ms** after the
   panel begins, in reading order: left column top→bottom, then right
   column, then the feature card last (Resources: Blog → Grader →
   Podcast). **Close**: no stagger — the panel fades/slides back in
   180–240ms and everything goes with it. A **140ms close-intent delay**
   runs before hiding so the pointer can travel from trigger to panel
   without flicker. Moving between the two triggers swaps content under
   one open panel (the panel does not close and reopen).
4. **Hamburger ↔ X.** A scale-and-blur icon swap: both glyphs stack in one
   grid cell; the active glyph is opacity 1 / blur 0 / scale 1, the
   inactive opacity 0 / blur 2px / scale 0.25; opacity, filter, and
   transform all transition **250ms ease-in-out**. Constants as component
   tokens (`--icon-swap-dur: 250ms`, `--icon-swap-blur: 2px`,
   `--icon-swap-start-scale: 0.25`). The rail's chrome swap (§2 fills,
   divider) crossfades over the same 250ms.
5. **Mobile drawers.** Exactly 004 §5: the drawer box's bottom edge draws
   down to its designed height over **250ms** — open on ease-in-out, close
   on ease-out — the header label static (the rebuilt geometry guarantees
   it), content revealed by the moving clip edge, chevron tracking the
   height in both directions, the rows below riding the whole-tick
   push-down. The `hard-shadow-square-md` offset grows 0,0 → 3,3 over
   **200ms** ease-out after the box lands; on close the shadow goes off at
   once. Single-open handoff runs both height animations concurrently.
6. **Panel open/close** (intent confirmed 2026-08-24 — §9 F10): the same
   footer grammar at panel scale — the panel draws down from the bar
   (height 0 → full viewport height, 250ms, open ease-in-out / close
   ease-out), borders and fill riding the box, content static under the
   clip edge, the panel's per-anchor shadow token growing from offset 0,0
   to its value over 200ms after landing; on close it goes off at once.
7. `prefers-reduced-motion: reduce` renders every part of this
   state-to-state, no transitions (icon swap included).

## 7 · Semantics, behavior, deliverable

- The chrome is a `<header>` containing a labeled `<nav>`. One DOM per
  structure, band-gated CSS; the desktop drawer subtree and the mobile
  panel subtree are each absent from the accessibility tree whenever
  closed or outside their bands.
- **Desktop triggers** (Solutions, Resources) — decision 2026-08-24 (§9
  F11): they **navigate and disclose**. Each is a real link (`<a>`) to its
  page carrying `aria-expanded`/`aria-controls`; the drawer opens on hover
  intent and on focus; activation follows the link; Escape closes the
  drawer and keeps focus on the trigger; drawer items are real links.
  Our Work / Pricing / Company / Login are plain links. On mobile the
  Solutions/Resources rows are **disclosure-only buttons** (the chips
  carry the links).
- **Mobile**: the menu button is a `<button>` with `aria-expanded`/
  `aria-controls`. The panel is a dialog (`role="dialog"`,
  `aria-modal="true"`): focus moves to the panel container
  (`tabIndex={-1}`, ring suppressed) — never auto-focused into a control;
  Escape and outside-click close; focus returns to the toggle
  (`preventScroll` both ways). Body scroll locks through `lib/scrollLock`
  only (the rebuild pages take the non-ScrollSmoother branch). Drawer
  headers are disclosure buttons exactly like the footer's; closed lists
  are hidden from the tree; single-open.
- Link targets follow the sitemap routes and are confirmed at build; the
  old site's routes are untouched.
- Server component under `design-system/v2/sections/`; client code is two
  islands — the desktop drawer controller (hover intent, 140ms
  close-intent, focus/Escape wiring) and the mobile panel island (toggle,
  scroll lock, single-open drawers). Zero hydration mismatches; the old
  site's bundles unchanged.
- QA surface: a permanent, noindexed **`/nav`** dev page rendering the
  chrome over a lattice fixture at all bands, drawer/panel states
  toggleable.
